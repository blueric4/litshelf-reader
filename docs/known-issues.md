## P1

### 0. 横向拖选会横穿多栏（用户 2026-10-11 截图）——**已修（硬性禁止跨栏）**
- 现象：在三栏论文页面上横向拖一下，选区把"左栏剩余 + 整段中栏 + 右栏开头"连成一条横穿三栏的
  高亮带。用户："论文的格式照理来说是做不到这么选取的才对。"
- 原因：文本层为了修"行间距跳行"已按**阅读顺序**重排 DOM，浏览器就按 DOM 顺序扩展选区，
  横向拖过栏缝时会把阅读顺序上连续、纸面上却不相邻的三段连起来。
- 已实现：`textOrder.ts` 的 `xWindowOf()`（按 x 覆盖投影找"文字块窗口"，比按行聚类的
  `columnsOf()` 稳，单测 3 例）+ `PdfViewer.clampToAnchorColumn()`（跨块就夹回锚点那一栏）。
- **但它在真实 CNKI 页面上不生效**：这类页面左侧常有一条**竖排页眉文字**，x 投影会被它"桥接"，
  三栏被算成一块 → 夹取不触发（实测横向拖选仍宽 932px、横穿三栏）。
- **已修**：栏带改用 pdf.js 的**文本项**（`columnBands.ts`：y 带覆盖率找通道、允许 ≤35% 行带被通栏标题压过、最小缝宽页宽 0.8%），
  111 页真实语料里多栏页从 7 页提升到 46 页；夹取修掉四个具体 bug（页码 off-by-one、方向用了 DOM 归一化端点、
  焦点落在容器就放弃、按 DOM 顺序取"栏末"）后**硬性锁住跨栏**（`ENABLE_COLUMN_LOCK = true`）。
- 验证：`tools/acceptance-columns.mjs` **16 条全过**（选区 x 275–343 落在栏 1 = 138–553 内）；
  `acceptance-selection.mjs` 45 条全绿且数字与改前逐位一致（零退化）；双向拖选/同栏纵向拖自测通过。
- **遗留体验问题（待做）**：带 `.markedContent` 的页面（样本文献 A 那篇 448/449 个 span 挂在 wrapper 下）因
  `reorderTextLayer` 的"必须同一父节点"保守分支不重排，DOM ≠ 阅读顺序 → 夹取只能给出很短的安全区间（该页 5 字）。
  治本 = 放宽重排限制（把 wrapper 的子节点也纳入排序）。
- **2026-10-11 收工时的进度**：`.markedContent` 重排 + 按栏带排序已落地并提交（`ef96b0f`，正向：同一处选区 5 → 36 字，完全落在栏内；
  columns 16 条 + selection 45 条全绿且数字与改前逐位一致）。
  **反向拖（末栏→左栏）已修并合并**（合并提交 80134d9）：样本文献 A p4 反向 **650 字、x-ratio 0.514~0.869，完全落在按下的右栏内**（≥4 次复现；改前 728 字跨栏）。
  机制已钉死：夹取本身生效，但 +416ms 时 **pdf.js 自己的选区处理**搬动 `.endOfContent`、给文本层加 `selecting` 类，
  使同一对边界点被整体重新解释成跨栏，而 Chromium **不补发 `selectionchange`** → 事件驱动的看护没机会纠正；
  `cloneRange()` 只存边界点，DOM 一变克隆体也被同样重新解释。
  已实现的修法（看护窗口内挂 `MutationObserver` + **强制重算**路径，带 8 次收敛上限、防自激）在分支
  **`wip/reverse-column-fix`** 上，`tsc` 0 / 292 单测绿 / 静态自查三项通过，但**端到端验证未完成**，已进主线（main 上复跑门槛：columns 16 ✅、selection 45 ✅、tsc 0、292 单测 ✅）。

### 1. 偶尔打开某篇论文长时间空白（文本层一个 span 都不挂）——**已按机制硬化（2026-10-11 凌晨）**
- 现象：打开后一直骨架屏，几十秒后仍无法划词；同一篇重启后又正常。用户在 8 篇真实中文期刊
  文献上遇到过，`tools/smoke-portable.mjs` 也撞到过两次（60 秒 0 span）。
- 观察：间歇性。开发态连续开关同一篇 6 轮全部 ~1 秒成功；打包态偶发。
- **硬化（A 方案）**：所有"可能永远不 settle"的 pdf.js 等待都加了上限 + 超时**取消任务**：
  - 等上一个渲染任务（`prevTaskRef`）→ **3 秒**，超时 `cancel()` 它（取消会让 promise reject，
    canvas 随即空出来）。老代码是裸 `await`，一旦上一个渲染悬挂，这一页就被**永久堵死** ——
    这是"偶发空白"最可信的机制。
  - `doc.getPage()` → 15 秒；`page.render()` → 25 秒（复杂页正常 8~20 秒）；文本层
    `getTextContent()` → 10 秒、`TextLayer.render()` → 10 秒。超时都取消并走**有界重试**，
    重试用尽升级到 `onStuck()` → 父级"重挂该页 → 重建文档换干净 worker"（每次文档一次）。
  - 清理函数额外取消上一个任务，避免卸载后还挂在等待里、让新页拿不到空闲 canvas。
- 回归网：**`node tools/acceptance-stability.mjs`**（70 项断言 / 约 4 分钟；自起 Electron 端口 9555 +
  隔离数据 + 真实论文只读）。覆盖：反复开关 12 轮 / 开关秒断（渲染在飞时取消）/ 连续缩放风暴 /
  跳页风暴（含"画布画好但文本层全空 ≥3s"的盯守）/ 论文切换 6 次 / canvas 与 worker 不泄漏，
  外加 **[7] 故障注入**。
- **故障注入的 A/B（决定性证据，同一脚本两版挨同一击）**：
  - 改前（`index-DoKBH2mD.js`，sha256 `c103c16f…`）：**✗ 8005ms 未恢复** —— 页面永久停在
    "白画布 + 骨架屏 + 旧文本层"（span=51 是旧的、画布宽已是新档位），看门狗静默（自愈标记 0 次）。
    机制：`await prevTaskRef.current` **裸等**永不 settle 的任务；看门狗第一句
    `if (textRef.current?.querySelector('span')) return;` 被**上一代残留的旧 span** 骗过。
  - 改后（`index-Dvsf-_MU.js`，sha256 `18714cfe…`）：**✓ 2357ms 恢复**（从按键起算 ≈3.06s，
    正是 3 秒超时），日志恰好一条 `[reader] 第 N 页等待上一个渲染任务超时，已取消它并继续`。
- 自然压力 5 类在**改前也全绿**（12 轮开关 471–734ms、14 页压力篇 ×6 672–884ms、缩放几何偏差
  0.0–0.01%、跳页/跳页风暴 318–357ms、6 次切换 497–844ms、canvas 3 且 12 轮无增长、console.error 0）
  → 这是"悬挂型"故障，不是流量型。
- 附带修好的一处隐患：看门狗新增 `paintedThisGen`（必须"这一代画完了"才放过），
  否则旧 span 会让它沉默。**该分支目前还没有被单独注入覆盖**（[7] 是超时兜底先救回来的）。
- 残留：**根因（pdf.js worker 为什么悬挂）仍未定位**；现在保证的是"悬挂也会在几秒内自愈，
  不会永久白屏"。

## P2

### 5. 右键菜单在"选区与 pending 不同步"时不给标注项（**既有问题**，非本轮引入）
- 场景：拖选 → 按 `1` 落一条高亮（pending 被清掉）→ **不点页面**直接右键空白处 →
  菜单只给"适应宽度/适应页面/加书签/复制引用"4 项，没有「高亮」。
- 取证：在**换官方 TextLayerBuilder 之前**的构建上跑 `UX_SECTIONS=F` 同样是红的
  （同一次还有"右键没有破坏选区"，那条已修）。所以这是既有问题，不是本轮引入。
- 试过的修法（**已回滚**）：给右键菜单加"最后一次非空选区"回退 → [F2] 转绿，但把**真正的
  无选区场景**带偏（"无选区时 4 项齐全且没有标注项"变红）。结论：不能只看"曾经选过字"，
  得区分"DOM 选区还在（可执行）"与"只剩历史（应提示重新选中）"。
- 现状：界面会提示「这段选区已经失效，请重新选中文字再标注」，不是静默失败；
  用例本身也标着"需 reviewer 复核"。

### 6. 跨页选择不支持
- 拖选跨页时不做批注（选区会被夹在起始页内）；这是当初为修"拖到空白变全选"定的边界。
- 影响：想高亮跨页的整段话时只能分两次。

### 7. 拖选不能跨页面之间的灰色缝隙
- 从一页拖到下一页的间隙会停在当前页末行。与第 5 条同源。

### 8. 缺 ErrorBoundary
- 渲染层若某组件抛错会白屏（没有兜底 UI 与"重试"入口）。reviewer 在第三轮提过，未做。

### 9. 极端页面尺寸 / 缩放上限
- 位图像素封顶 1600px：400% 缩放下大页面会略微软（清晰化重绘以 1600px 为上限）。
- 极大页面（如 A0 图纸）未做特别处理。

### 10. "更多筛选"入口可发现性
- 左侧默认只显示 4 项（全部文献/最近添加/在读/星标），其余筛选要去设置里打开；
  有用户可能找不到入口。

### 11. 设置项被手改成非法类型
- `settings.json` 里把手写字段塞成错误类型（如 `sidebarExtraFilters: 42`）已有归一化兜底，
  但其它字段没有逐一做类型防御。
