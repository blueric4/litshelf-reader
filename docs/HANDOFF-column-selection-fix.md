## 0. 一句话结论

"多栏论文里划词不许跨栏"这个功能**还没修完**：整页级的大范围误选已经消除，但**仍有把选区右端越到相邻栏的泄漏**
（实测右端停在 613，而按下那一栏的右界是 523 / 555 / 545）。**目前线上发布的整合版含更严重的回归**（见 §6）。

## 1. 用户可见症状与复现

- 症状 A（已修）：某页拖 2~3 行 → **整页文字几乎全被选中**（一次 1913 字 / 2102 个 rect）。出现在**带整幅图注/表格的页面**。
- 症状 B（未修）：栏 1 内拖 2~3 行 → 选区**右端越过栏缝**进到栏 2（右端固定 613）。出现在**正文两端对齐、行末单字被推进栏缝**的页面。
- 复现：打开 8 篇真实中文期刊论文中的任意一篇（`$env:LITSHELF_SRC_LIB` 指向其目录），在第 2~9 页任一双栏页的**栏 1** 内纵向拖 2~3 行。

## 2. 真因（三条，全部有原始数据支撑）

> **更正（2026-10-11，以本段为准）**：下面 §2.1 / §2.2 的原诊断被后续取证推翻，保留原文仅供追溯。
>
> **真因：栏带坐标没有减去页面原点。** 真实 CNKI 论文的 `page.view` 左下角是 (28.35, 14.17)（CropBox 偏移），
> pdf.js 渲染时会减掉它（`viewport.transform` 的平移量就是 -28.35），而产品的 `columnBands` / `columnRegions`
> 直接用了原始 `transform[4]/[5]`。结果整套栏带、分区、重排的比例都整体偏移约 54px（x0×scale）：
> - 栏 1 的右界被算成 PDF x≈317 ≈ 像素 612 —— 这**就是**"右端停在 613"的来源。613 不是 span 归属的问题，而是栏带边界本身；
>   `「连」[595~613]` 在真实版式里本来就是栏 2 的开头字（栏 2 从 594 起）。
> - 栏内靠左的 span 落进"栏外"的桶，被排到整页末尾 —— 这**就是**症状 A（苏敬勤 p6 栏 1 选中 1913 字）的来源，
>   **不是**页面级开关。
>
> **修复（已落地）**：
> 1. `columnBands.ts::itemsInViewSpace()`：把文本项平移到 `page.view` 原点，分区与栏带都只用它的输出；
> 2. `PdfViewer.tsx`：取文本项的参数与 TextLayerBuilder 完全一致（`TEXT_LAYER_PARAMS = { includeMarkedContent: true, disableNormalization: true }`）。
>    参数不一致时文本项数量对不上（实测 1438 vs 1392），span 序号与文本项序号错位；
> 3. 打标只对 `str` 非空的文本项做：pdf.js 的 `#appendText` 只给 `hasText` 为真的项挂 span。
>
> **验证（苏敬勤 p6 栏 1，同一拖动）**：修复前 `1913 字 rect=2102 越界 995`；修复后 `256 字 rect=367 越界 0`。
> 全量 `col-scan`：修复前 22 处失败（16 处越界 + 6 处 0 字），修复后 14 处（7 处越界 + 7 处 0 字）。
> 其中 7 处"越界"已逐页核对为 **col-scan 自身模型的误报**：模型算出的栏带比产品栏带窄（如宁德时代 p2 模型栏 1 为 171~523，
> 产品为 143~555），而选区全部落在产品栏带之内；这一点见 §4 的"已知限制"。

### 2.0 原诊断（已被上面的更正推翻，仅供追溯）

### 2.1 页面级开关（本轮引入的回归，已在 wip 分支修掉）
上一版为修混排页（整幅摘要 + 双栏正文）加了"按 y 分区"，其中带了一条**页面级结论**：
"整页全局栏带 < 2 → 当作单栏 → **整个关掉夹取**"。而在**有整幅图注/表格**的页面上，
`columnBandsFromItems()` 的 y 带覆盖统计会被图注/表格行压过 → 全局只给出 1 栏 → 夹取被关掉 → 拖 2~3 行变成整页选中。
- 证据：苏敬勤那篇 p6 栏1 选区 `x=[150~1007] 1913 字 rect=2102`；p6 末栏 `1162 字`；p9 末栏 `966 字`。

### 2.2 端点归属用 DOM span 的 rect 判（**未修，当前泄漏的直接原因**）
正文两端对齐会把**行末单个汉字推进栏缝**：实测 `[595~613]「连」`，而栏缝是 555~595。
我们按"span 中心落在锚点栏内"挑夹取端点，于是这些 gutter 里的字被算进锚点栏 → 选区右端一律停在 **613** ✗。
- 证据：页3 栏1=[146~555] 选区 `x=[186~613] 203 字 越界rect=12`；页4 栏1=[146~545] `x=[181~613] 229 字 越界rect=14`；
  页2 栏1=[171~523] `x=[191~613] 156 字 越界rect=28`。

### 2.3 度量口径的坑（会让诊断走偏，务必按此口径）
- **行宽必须取"该行最宽的 x 簇"**，不能取"整行最左到最右" —— 双栏页左右两栏的行 y 几乎相同，
  取最左到最右会把**每一行都判成通栏**（曾产生"通栏行 22 连 7"的假值，导致 6 篇论文全被自校验否掉）。
- **"行被拆开"的判据要按 span 而不是像素**：中文两端对齐行内相邻 run 的正常间距就有 **10~15px**，
  用固定 12px 阈值会把版式间距误报成断档。正确口径：*某行"选全" ⟺ x 落在选区首尾之间、y 属于该行的所有 span 都被选中；
  只有出现"未被选中的 span"才算断档*（实测按此口径为 **0**）。
- **x 覆盖率的分母**要取"该页文字内容 x 范围"，不是别的口径（曾算出 77% 的假失败，实际 792/800 = 99%）。

## 3. 处方（按顺序做，做完必须过 §4 的门槛）

### 第 1 步：端点归属改用 **pdf.js 文本项**（消灭 613 泄漏）
- 栏带的**唯一权威来源**是 `page.getTextContent().items`（每项自带 `transform[e,f]`、`width`、`height`），
  把它们换算成页面坐标（y 向下）后交给 `columnBands.ts`。**不要**用 DOM 里 span 的 rect 判"这个字属于哪一栏"。
- 为每一页建一份 **item → 栏索引** 的映射；夹取端点的候选**只能是**满足
  `item.x >= band.start - 2 && item.x + item.width <= band.end + 2` 的文本项（`safeLo / safeHi` 用**相邻栏缝**卡出来）。
- 再把这些文本项映射回文本层里的 span 元素（按渲染顺序/`str`+位置匹配）用于构造 `Range`。

### 第 2 步：把纠正从"事后"提前到"拖动中"
- 现状是"浏览器先按 DOM 顺序拉出选区 → 我们事后夹"。请改为在 `mousemove`（`pressed === true`）时就用
  第 1 步的映射算出目标端点：焦点栏 ≠ 锚点栏 → **立刻**把选区设成"锚点 → 锚点栏边缘的文本项"。
- 事后夹取（`clampToAnchorColumn`）保留为兜底；`MutationObserver` + 强制重算那条路径继续保留
  （pdf.js 会在选区变化时搬 `.endOfContent`，且**不补发** `selectionchange`；`cloneRange()` 只存边界点，DOM 一变就被重新解释）。

### 第 3 步：判据与开关（不要做的事）
- **永远不要用页面级结论开关夹取**。夹取与否只看**锚点所在的行/分区**：
  该行/分区只有一条栏带 → 不夹；多栏 → **硬性禁止跨栏**。
- "通栏"判据从严：该行是**单个 x 簇** 且跨度 **≥80% 内容宽**，并且该行纵向邻域（±2 行）内没有多栏文字；
  夹在多栏段之间的**孤立宽行**（小标题/表格行/图注行）**降级为多栏**、沿用邻居栏带。
- `reorderTextLayer()` 的重排**仍按"整页模型是否多栏"门控**（`orderBands.length >= 2`），否则走老的 `orderTextSpans`。
  这条是保住 45 条手感用例的关键：去掉它，"行间距拖 31 字 → 2 字""拖到空白 308 字 → 696 字" 会立刻变红。

| 文件 | 函数 | 要点 |

## 5. 环境与坑（每条都是踩过的）

1. **Electron 单实例锁**：所有桌面脚本串行跑；端口约定 `9444`（acceptance-columns）/ `9333`（探针）。
   **只 kill 自己 spawn 的进程树**，不要全局 `Get-Process electron | Stop-Process -Force`（会把别人的运行一起杀掉，
   曾因此产生一批假数据）。`acceptance-selection.mjs` 收尾会清掉开跑前就存在的 electron —— 没人在跑时再执行它。
2. **dist 是共用产物**：并发构建会让正在跑的实例懒加载 chunk 404 → 假失败。做法：跑批前构建一次、记录指纹，
   每套跑完复查指纹，中途变化就把该轮**作废**。
3. **不要用 PowerShell 的 `Get-Content/Set-Content` 改源码/脚本**（会把 UTF-8 中文按 GBK 写坏，已踩过两次）。
   用编辑工具或 Node 的 `fs.writeFileSync(..., 'utf8')`。
4. **合成鼠标偶发 0 字**：整段拖动期间一条 `selectionchange` 都没有（浏览器压根没开始拉选区），
   命中与样式都正常 → 探针要**加重试**，不要据此改产品代码。
5. **`.endOfContent`**：pdf.js 会在选区变化时把它插到锚点旁并设成整层大小（同一对边界点被重新解释、文字没变但 rect 横贯整页）；
   处理办法是把它**挪回末尾、清掉行内宽高**，并像 pdf.js 自己的 `reset()` 一样**摘掉 `selecting` 类**
   （否则它会变成盖住整层的可选中块，那片区域"一个字都选不中"）。
6. **`cloneRange()` 只存边界点**：DOM 一变克隆体被同样重新解释 → 光靠"锁住旧区间"救不回来，
   必须走 `MutationObserver` + **按几何强制重算**（带收敛上限，且**正常同栏选区永不重算**，否则 45 条必崩）。
7. **"按下点若落在上一次的选区里，Chromium 不会重新拉选区"**（会塌陷）→ 探针每次拖动前先用真实点击清选区。
8. 论文目录**只读**：任何脚本、打包、验证流程都不得写入；跑前后用 `名称|大小|mtime` 或哈希比对证明零变化。

## 7. 发布纪律（这个仓库是**公开**的）

- **不得出现**：本机用户名、`C:\Users\...` 路径、真实论文标题/作者名。文档与脚本里用占位符
  （`<本地文献目录>`、`样本文献 A/B/C`），工具脚本读环境变量（`LITSHELF_SRC_LIB`、`LITSHELF_PREFER`）。
- **推送前必须查历史**：文件脱敏 ≠ 历史脱敏（`git log -p` 能看到旧提交里的敏感串）。
  做法：确认要推的提交 diff 与**提交信息**都干净；必要时把若干提交 `git reset --soft origin/main` 压成一个再提交（本仓库做过一次）。
- 上传 Release 附件用 `git credential fill` 在内存里取 token，**不打印、不落盘**；替换附件时先删旧再传新，避免同名两个 zip。
- 打包：`node tools/make-portable.mjs` → `D:\dsh\文献架整合`；自检 `tools/smoke-portable.mjs`（13/13）+ 真实论文探针（8/8，确认只读）。
