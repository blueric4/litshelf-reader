## 1. 这次修好了什么（给用户看的 changelog）

### 🐛 修复：双栏 PDF 划词会跨栏（本次重点）

在**两栏排版的 PDF**（尤其页面上方有通栏表格时）里，从**左栏**按住往下拖，
高亮会蹿到右栏 —— 这是本版修复的核心问题。

**根因**（值得写出来，因为它解释了为什么以前怎么调都调不好）：
底层几何代码把"**整段文字的矩形**"当成"**单个字的矩形**"用了。
于是用来判断"两个字之间有多远"的那个量，**算出来是负数**（实测行内间隙中位数 −828.5），
任何"多大算分栏缝"的阈值都无从谈起 —— 之前的多次参数调整全是白费，因为**分母本身是错的**。

**修好之后的表现**（真实鼠标 + 截图验收）：
| 用例 | 结果 |
|---|---|
| 两栏正文左栏内竖拖 | 选中 135 字 / 7 条高亮；最右端 553 < 中线 572；**不跨栏**；相邻高亮缺口 ≤11px（**连续，不中断**） |
| 表格单元格内拖 | 只选中该单元格内容，不串到相邻列 |
| 分块结构（第 4 页） | **114 块 → 47 块**；左右两栏各 **100%** 落在本栏块内；跨栏块 **0** |

### 🐛 修复：缩放/换页后立刻按下，选不中（约 0.25 秒的"失灵窗口"）

缩放或换页会触发重绘，而重绘期间该页的文本层会被临时注销，导致这瞬间按下**完全没反应**。
现在缩放/换页后可以**立刻**拖选。
实测：修复前连续 4 轮都出现"缺页"（最少时引擎只认得 0 页），修复后 **缺页 0 次、起锚 75/75**。

### 🐛 修复：点字错位（点到这个字，选中的却是旁边那个）

判断"鼠标落在哪个字上"的几何依据用错了，导致上下标、括号等相邻处会选到隔壁的字。
实测 5 页共 **107619** 个采样点：正确率 **99.70% → 100.00%**，**零劣化**。

## 3. 发版步骤

### ① 打包（已生成，需要重打时执行）
```bash
node tools/make-portable.mjs      # → D:\dsh\文献架整合
node tools/smoke-portable.mjs     # 期望：13 通过 / 0 失败
```

### ② 压 zip
```bash
powershell -NoProfile -Command "Compress-Archive -Path 'D:\dsh\文献架整合\*' -DestinationPath 'D:\dsh\litshelf-v1.0.1-win-x64.zip' -CompressionLevel Optimal"
```
> zip 与整合版目录都在**仓库之外**（`文献架整合/` 在项目上一级），不会进 git。

### ③ 推代码
```bash
git push origin <当前分支>          # 或先合并到 main 再 push
```
> ⚠️ **不要把 zip 或 `文献架整合/` 提交进仓库**：GitHub 单文件上限 100 MB，
> 而整合版解压后 446 MB（`.gitignore` 已拦截 `*.zip`、`文献架整合/`）。
> 大文件一律走 **Release 资产**（无此限制）。

### ④ 建 Release 并上传资产
本机没装 `gh`，用网页最省事：<https://github.com/blueric4/litshelf-reader/releases/new>

- **Tag**：`v1.0.1`（`v1.0.0` 已存在，不要复用；若想覆盖旧版请先删旧 tag）
- **Title**：`v1.0.1 — 修复双栏 PDF 划词跨栏`
- **正文**：复制上面第 1 节
- **附件**：把第 ② 步的 `litshelf-v1.0.1-win-x64.zip` 拖进去
- 发布后建议**编辑 Release 正文**，把这一段放最前面：
  > 解压后双击 `文献架 LitShelf.exe` 即用，无需安装 Node.js。
  > 数据存在 `%APPDATA%\文献架 LitShelf`，整包可以随便拷贝/换电脑。
