# 划词选取：引擎接管版（selectionEngine）

## 这是什么

PDF 阅读器里的划词，**不再使用浏览器原生选区**。原因写在 `selectionEngine.ts` 顶部：
浏览器按 **DOM 顺序**扩展选区，而中文期刊的 PDF **内容流顺序 ≠ 版面顺序**（常常左右栏交替），
"两个选区互相打架"是过去 7~8 轮修复全部失败的根本原因。

## 三个关键点（少一个都不成立）

1. **文本层 `user-select: none`**（`PdfViewer.tsx` 的样式里，`.rd-pdf-text, .rd-pdf-text *`）
   —— 关掉原生选区这条路。
2. **拖动 = 指针位置**：按下点的字 = 锚点，指针当前的字 = 焦点，**每帧重新算两端**
   （不是"在浏览器选区上做纠正"）。
3. **焦点只允许取"锚点那一栏"里的字**（按 `flowClass` 分栏，跨栏在结构上不可能）；
   **高亮自己画**，按行合并 —— 每行一条矩形，行内不留缝。

## 文件

| 文件 | 作用 |
|---|---|
| `src/renderer/reader/selectionEngine.ts` | 引擎本体（自包含，不依赖 React/pdf.js） |
| `src/renderer/reader/PdfViewer.tsx` | 接线：鼠标事件、高亮层、把选区翻成工具条/批注要的形状 |

## 验证方式（用户指定的唯一口径：**鼠标 + 截图**）

- 隔离验收页：`node tmp/sel-harness/make.mjs && node tmp/sel-harness/run.mjs`
  （真实浏览器、真实鼠标事件、截图到 `tmp/sel-harness/shots/`）
- 产品内验收：`node tmp/sel-harness/app-verify.mjs`
  （真实应用窗口、真实鼠标事件、截图到 `tmp/sel-harness/shots-app/`）

两者都**不做"我的探针说通过"式结论**，只输出：拖完之后高亮的矩形、截图、以及
"选区里有没有出现锚点栏之外的字"。

## 已知还会出问题的地方（诚实记录）

1. **反向拖（从右栏往左栏拖）**：锚点若落在页眉/通栏标题那一行上，命中会把它算成
   通栏行，选区只剩几个字。根因是"指针落在行间空隙时的吸附顺序"还没完全调好。
   正向拖（左栏内竖拖、左栏→右栏横拖）已实测正确。
2. **通栏行不许划词**：页眉/页脚/跨栏标题不能拖出选区（真实阅读器一般也如此）。
   如果希望"跨栏标题也能选"，需要单独做（要放行它的整行矩形）。
3. 双击选词、三击选行**没做**（用户明确不需要）。
4. 复制走 `document` 上的 `copy` 事件自己写剪贴板；右键菜单里的"复制"若走别的事件链，
   需要再确认一次。
